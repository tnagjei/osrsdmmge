# SEO 索引优化方案

> 针对 Google Search Console 显示的 "已发现 - 尚未编入索引" 问题

**创建日期**: 2026-02-09  
**受影响页面**: 24 个内页（en/fi/sv/no 各 6 个子页面）  
**新增页面**: 4 个英文 Blog 文章页（`/blog/<slug>/`，已加入 sitemap）

## 硬约束（老板确认）
- **绝不改动首页（/）的 Title 与 Meta Description**（技术 SEO 只做 canonical/hreflang/URL 规范化/sitemap/内链等信号）

---

## 问题诊断

Google 已发现这些页面但选择不收录，通常原因：
- 页面内容价值不足
- 与其他页面内容重复
- 内部链接权重不够
- 网站整体权威性较低

补充：结合当前项目结构（根路径 `/` + 多语言 `/en|fi|sv|no/`）与现网页面信号，"已发现-尚未编入索引" 还常见于：
- URL 规范化信号混乱：同一内容存在多套 URL（例如 `/` vs `/en/`），canonical/站内链接/sitemap 不一致，导致 Google 认为重复并延后索引
- 多语言页面内容高度重复：fi/sv/no 页面若仍是英文主体内容，容易被判定为重复或低价值，仅选择一个版本索引
- Legal 页面内容/主题不一致：terms/privacy 若残留不相关文案（例如与站点主题不符），会影响整体质量判断与 URL 选择

### 阶段二：多语言内容本地化

#### 2.1 检查翻译状态
- [ ] 审核 fi/ (芬兰语) 页面是否有真实翻译
- [ ] 审核 sv/ (瑞典语) 页面是否有真实翻译
- [ ] 审核 no/ (挪威语) 页面是否有真实翻译

#### 2.2 决策点
- **如果无法提供真实翻译**：考虑暂时移除非英语版本，集中资源
- **如果保留**：必须确保内容差异化，避免重复惩罚

#### 2.3 临时止损策略（推荐）
在“真实翻译”尚未完成前，为避免重复内容拖累收录选择，可选其一：
- 方案 A：fi/sv/no 继续保留对用户可见，但对搜索引擎 `noindex`，并从 sitemap 移除（等翻译完成再恢复）
- 方案 B：直接下线 fi/sv/no（301 到英文对应页面），待翻译完成再重新上线

### 阶段三：技术 SEO 优化

#### 3.0 URL 规范化（高优先级，先于其它技术项）
目标：给 Google 一个“唯一版本”的强信号，减少重复页面导致的索引延迟。

- [x] 决策：采用方案 A：英文使用根路径（`/about/`、`/help/`…），将所有 `/en/*` 永久重定向（301）到根路径对应页面（Vercel: `vercel.json` redirects）
- [x] 统一站内链接：Header/Footer/正文链接全部指向规范 URL（避免同时出现 `/` 与 `/en/` 两种入口）
- [x] 统一 sitemap：仅提交规范 URL；非规范 URL（如 `/en/*`）不出现在 sitemap

#### 3.1 Canonical 与 hreflang 校验（高优先级）
- [x] 每个页面 canonical 指向“自身的规范 URL”（英文页 canonical 指向根路径版本；fi/sv/no 指向各自语言路径）
- [x] 多语言页面输出完整 hreflang 互链（en/fi/sv/no + x-default），并确保 `x-default` 指向英文根路径版本
- [x] 确认 canonical/hreflang 与实际可访问 URL（200/301）一致（`/en/*` 永久重定向到根路径）

#### 3.1 内部链接强化
- [ ] 首页正文区域添加子页面入口链接
- [ ] 子页面之间添加"相关内容"交叉链接
- [ ] Blog 文章底部添加"推荐阅读"模块

#### 3.2 Sitemap 优化
- [x] 确认 sitemap.xml 包含所有需要收录的页面（含 `/blog/<slug>/`）
- [ ] 为重要页面设置更高的 priority 值
- [ ] 添加 lastmod 日期并保持更新

#### 3.3 页面质量提升
- [ ] 检查 Core Web Vitals 分数（目标: 所有指标绿色）
- [ ] 确保移动端完全可用
- [ ] 图片添加 alt 文本
- [x] Legal 页面（terms/privacy）内容与站点主题一致；避免残留无关模板文案

#### 3.4 Vercel 部署配置（高优先级）
- [x] `vercel.json`：配置 `/en/*` -> `/*` 的 301（与英文根路径 canonical 一致）
- [x] `vercel.json`：配置安全头与基础缓存头（注意：Vercel **不读取** `public/_headers` / `public/_redirects` 作为生效配置）
